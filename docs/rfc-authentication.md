# RFC：面向网站测试的认证与凭据管理

> 历史 TypeScript RFC 的中文整理版，保留原文件名。当前 Python 认证实现位于 `src/auth/`，路径对应关系见 `MIGRATION_PLAN.md`。本文描述原提案；计划中的 OAuth、SSO 或其他能力不能视为已实现。

## 摘要

许多网站的主要功能需要登录后才能访问。原提案设计了一套认证能力：识别登录页面、管理测试凭据、执行登录流程、保存浏览器会话，并用不同账户测试权限差异。目标是在探索和单页测试中覆盖仪表盘、个人资料、结账等受保护页面。

## 问题与目标

没有认证支持时，代理只能访问公开页面，无法验证用户专属功能或角色权限。电商、SaaS、社交和其他应用中的核心流程都可能因此漏测。认证方案需要兼顾：

1. 凭据的安全存储和读取。
2. 登录页面与表单的自动识别。
3. 表单登录、会话恢复和过期处理。
4. 测试账户之间的隔离。
5. 多因素认证及更复杂登录流程的可扩展性。

### 组件职责

| 组件 | 职责 |
|---|---|
| `AuthenticationManager` | 协调已有登录态、会话恢复、登录检测和实际登录 |
| `CredentialProvider` | 按应用标识读取测试凭据，连接配置与持久化存储 |
| `CredentialStorage` | 加密保存凭据，避免明文持久化 |
| `LoginFlowDetector` | 查找登录页面、用户名或邮箱字段、密码字段及提交按钮 |
| `LoginExecutor` | 填写表单、提交并检查是否登录成功 |
| `SessionManager` | 保存和恢复 cookie、浏览器存储状态及过期信息 |
| `MFAHandler` | 处理可自动化的 TOTP；其他方式可能需要人工介入 |

当前代码中的对应文件见 `src/auth/`。账户标识、登录方法等程序字段保持英文；展示给用户的说明使用中文。

## 认证顺序

1. 检查页面是否已经处于登录状态。
2. 尝试恢复保存的浏览器会话，并再次验证登录态。
3. 如仍需登录，查找当前页面的登录表单，必要时尝试常见登录路径。
4. 获取对应应用的测试凭据，执行表单登录。
5. 验证登录结果；成功后保存会话，供后续测试复用。

登录是否成功不能只靠提交按钮点击结果判断；应结合页面 URL、用户菜单、退出入口或可见错误。不同网站的页面结构可能需要额外适配。

## 配置与使用

交互式 CLI 会询问是否需要登录，以及使用新凭据还是已有凭据。MCP 工具使用 `authRequired`、`authEmail`、`authPassword` 和 `authAppIdentifier` 等字段。环境变量用于模型服务；认证凭据按应用标识单独管理。

~~~bash
uv run python -m src.index
~~~

测试不同权限时，应在目标应用中预先创建有相应权限的专用测试账户，再分别运行测试。仅改变代理的账户名称不会改变目标应用授予的角色。

## 原提案的实施阶段

1. 建立认证管理器、凭据提供器与加密存储，编写存储测试。
2. 实现登录检测、表单登录和结果验证。
3. 保存与恢复 cookie、浏览器存储状态，并处理会话过期。
4. 扩展 TOTP、OAuth、SSO 和复杂登录流程。
5. 接入探索代理、单页代理、CLI 与 MCP 工具。

阶段四中的扩展能力是原规划，当前支持情况应检查 `src/auth/`。

## 安全与隐私

- 使用专用测试账户，按环境区分开发、预发与生产凭据。
- 不在代码、报告或日志中写入密码、令牌和密钥；不要提交 `.env` 或 `.auth.key`。
- 对本地凭据和会话文件设置适当的文件系统权限，并定期轮换测试凭据。
- 如确需管理员权限，应在目标应用中明确授予测试账户，并限制测试范围。
- 支付流程使用测试卡，不保存真实支付凭据。
- 保留原始错误便于排查时，也要避免把敏感响应体写入报告。

原 RFC 提到了加密存储、访问审计和外部密钥库等方向；实际算法与审计能力必须以当前实现为准，不能仅凭提案假定。

## 权衡、指标与待决事项

认证扩展了可测页面和角色覆盖，也增加配置成本、凭据维护与安全风险。短信或邮件验证码可能无法在无头浏览器中自动完成。衡量指标包括受保护页面覆盖率、登录成功率、会话恢复耗时和凭据泄露事件。

仍需决定是否接入外部密钥库、如何处理短信或邮件多因素认证、是否跨运行共享会话，以及是否自动轮换测试凭据。原提案倾向先使用本地方案和 TOTP，再逐步扩展。

## 备选方案

仅测试公开页面实现最简单，但覆盖不足；完全依赖人工登录会打断自动化；复用浏览器配置文件容易启动，却较难按账户管理和控制。原提案选择独立的认证与凭据管理层。
