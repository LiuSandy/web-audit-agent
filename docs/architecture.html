架构总览：从三个入口到一份报告

三个入口收敛到同一个 explore() 生命周期；发现问题的主路径是监视器旁路而非 LLM 主动记录；每步状态落库支撑会话恢复。图 1 看系统，图 2 看单步，图 3 看单页模式的差异。

系统总览

  • 编排只写一份。三个入口不各自实现循环：都落到 src/cli/core/runner.py 的 explore()，退出码（0 成功 / 1 失败 / 2 用法 / 130 中断）、报告与恢复契约只维护一处。MCP 入口在这层之外多一张 active_tests 状态表，供 get_test_status 轮询、stop_test 置停。
  • 发现问题靠旁路，不靠 LLM 自觉。LLM 每步只产出「下一步做什么」的 JSON 决策，record_finding 只是补充；控制台/网络错误由页面事件缓冲，自动扫描统一消费。推论：最后一步若是 record_finding 或 finish，缓冲里的错误不会进报告（问题清单 #5）。
  • 每步落库是恢复的基础。save_state() 每步执行一次；--session-id 重新进入时 load_state() 还原队列与历史，start() 校验目标站点一致后才复用已存认证。
